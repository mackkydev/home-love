# บ้านใจ — Home Organizer

Next.js PWA สำหรับบันทึกข้อมูลในบ้าน ข้อมูลออนไลน์ใช้ Supabase Auth, PostgreSQL และ Storage โดยกำหนดสิทธิ์ด้วย Row Level Security (RLS)

## เริ่มใช้งานในเครื่อง

```bash
npm install
npm run dev
```

หากยังไม่ได้ตั้งค่า Supabase แอปยังใช้ข้อมูลในเบราว์เซอร์ตามเดิม

## ตั้งค่า Supabase

1. สร้าง Supabase project และเปิด SQL Editor
2. รัน [migration หลัก](supabase/migrations/20261010000000_initial.sql) เพื่อสร้างตาราง, RLS และ Storage bucket แบบส่วนตัว จากนั้นรัน [migration รหัสเชิญ](supabase/migrations/20261010010000_household_invites.sql) และ [migration ผู้ดูแลระบบ](supabase/migrations/20261010020000_admin_signup_control.sql) ตามลำดับ
3. ใน Authentication > URL Configuration ตั้ง Site URL เป็น URL ของเว็บบน Vercel และเพิ่ม `http://localhost:3001` ใน Redirect URLs สำหรับการพัฒนา (เพิ่มพอร์ตที่ใช้งานจริงด้วย)
4. เปิด Email provider ใน Authentication เพื่อใช้สมัครสมาชิกและเข้าสู่ระบบด้วยอีเมล/รหัสผ่าน โปรเจกต์ Supabase ปกติจะให้ยืนยันอีเมลเมื่อสมัครใหม่
5. คัดลอก `.env.example` เป็น `.env.local` แล้วกรอก Project URL และ publishable key หรือ anon key (ไม่ใช้ service role key ใน frontend)
6. รีสตาร์ตเซิร์ฟเวอร์ Next.js

เมื่อเข้าสู่ระบบครั้งแรก แอปสร้างบ้านส่วนตัวอัตโนมัติ หากบัญชีนี้ยังไม่มีรายการออนไลน์และมีบันทึกเดิมในเบราว์เซอร์ แอปจะแสดงปุ่มให้เลือกนำเข้าข้อมูลเดิม โดยไม่ลบต้นฉบับในเบราว์เซอร์ รูปภาพและเอกสารจะถูกย้ายเข้า Storage ส่วนตัวหลังจากกดนำเข้า

เจ้าของบ้านกดชื่อบ้านด้านบนเพื่อสร้างรหัสเชิญ ส่งรหัสให้สมาชิกในครอบครัว สมาชิกสมัครและเข้าสู่ระบบด้วยบัญชีของตน แล้วกดชื่อบ้านเพื่อกรอกรหัส รหัสใช้ได้ครั้งเดียวและหมดอายุใน 7 วัน สมาชิกสลับระหว่างบ้านส่วนตัวและบ้านที่เข้าร่วมได้ในหน้าจอเดียวกัน ผู้ที่เคยเข้าใช้ด้วยลิงก์อีเมลสามารถตั้งรหัสผ่านในหน้าจัดการบัญชีและบ้าน หรือใช้เมนู «ลืมรหัสผ่าน» ที่หน้าเข้าสู่ระบบ

## เปิดหน้าจัดการผู้ดูแลระบบ

หลังรัน migration ผู้ดูแลระบบแล้ว ให้ไปที่ Supabase Dashboard > Authentication > Hooks และเปิด **Before User Created** โดยเลือก Postgres Function `public.before_user_created_signup_gate` แล้วบันทึก ขั้นตอนนี้จำเป็นเพื่อให้ปุ่มปิดรับสมัครบล็อกการสมัครผ่าน Supabase API ด้วย หากไม่ได้เปิด hook หน้าเว็บจะซ่อนปุ่มสมัคร แต่ API ยังสร้างบัญชีได้

หากก่อนรัน migration มีบัญชีเดียว ระบบจะให้บัญชีนั้นเป็นผู้ดูแลโดยอัตโนมัติ หากมีหลายบัญชีหรือยังไม่มีบัญชี ให้เลือกบัญชีของตนใน Authentication > Users แล้วนำ User ID ไปเพิ่มใน SQL Editor:

```sql
insert into public.app_admins (user_id)
values ('ใส่-User-ID-ของบัญชีผู้ดูแล')
on conflict do nothing;
```

ออกจากระบบแล้วเข้าใหม่เพื่อให้เมนู **ผู้ดูแลระบบ** ปรากฏในหน้าจัดการบัญชีและบ้าน ผู้ดูแลสามารถเปิดหรือปิดการสมัครใหม่ได้ สมาชิกเดิมยังเข้าสู่ระบบได้แม้ปิดรับสมัคร การปิดรับสมัครจะหยุดบัญชีใหม่ทั้งหมด รวมถึงคนในครอบครัวที่ยังไม่เคยสมัคร

## ตั้งค่า Vercel

1. Import repository `mackkydev/home-love` ใน Vercel
2. ตั้ง Environment Variables `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` จาก Supabase project
3. Deploy แล้วเพิ่ม URL จริงใน Supabase Authentication > URL Configuration

ค่าทั้งสองเป็นค่าที่เปิดเผยได้ในเว็บ สิทธิ์เข้าถึงข้อมูลบังคับโดย RLS ฝั่งฐานข้อมูล อย่าใส่ secret key หรือ service role key ใน `NEXT_PUBLIC_` variables

## สถานะปัจจุบัน

- มีการสมัคร/เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน พร้อมตั้งรหัสผ่านใหม่และจัดเก็บบันทึกออนไลน์
- ตารางรองรับสมาชิกหลายคนต่อบ้านและบทบาท `owner`, `admin`, `member`
- เจ้าของหรือผู้ดูแลสร้างรหัสเชิญแบบใช้ครั้งเดียวได้ สมาชิกเข้าร่วมและสลับบ้านได้ ยังไม่มีหน้าจอเปลี่ยนบทบาทหรือถอดสมาชิก
- ยังไม่มีระบบ subscription หรือการรับชำระเงิน
- บันทึกที่ผู้ใช้แก้ไขจะซิงก์หลังจากหยุดพิมพ์สั้น ๆ หากการซิงก์มีปัญหา แอปจะแสดงข้อความผิดพลาด
