# จัดการผู้ใช้ บ้าน และโควตา

เปิดจาก **ตั้งค่า → จัดการระบบ** หรือ `/admin` โดยใช้บัญชีที่อยู่ใน `public.app_admins` เท่านั้น ทุกคำสั่งตรวจสิทธิ์ที่ฐานข้อมูล สมาชิกทั่วไปไม่สามารถเรียก RPC เพื่อแก้โควตาเองได้

## ก่อนเปิดใช้งาน

1. สำรองฐานข้อมูลและทดสอบใน Supabase staging ก่อน ใช้ migrations เดิมทั้งหมดของโครงการ แล้วรัน `supabase/migrations/20261113000000_admin_accounts_quotas.sql` ใน SQL Editor เพียงครั้งเดียว
2. ตั้งค่า `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (หรือ `NEXT_PUBLIC_SUPABASE_ANON_KEY`) และ **`SUPABASE_SECRET_KEY` ฝั่งเซิร์ฟเวอร์เท่านั้น** รองรับ `SUPABASE_SERVICE_ROLE_KEY` สำหรับโปรเจกต์ที่ยังใช้คีย์เดิม ห้ามใส่คีย์ลับในตัวแปร `NEXT_PUBLIC_*`
3. Deploy แอปรุ่นนี้ทันทีหลัง migration เนื่องจาก migration ปิดการอัปโหลดตรงเข้าบักเก็ต `household-files` ของแอปรุ่นเก่า แล้วใช้ `/api/household-files` แทน ควรจัดช่วงบำรุงรักษาสั้น ๆ ให้สองขั้นตอนนี้อยู่ติดกัน
4. ตรวจบัญชี admin และสมาชิกจริง: ปิด/เปิดผู้ใช้, เพิ่มบ้านและสมาชิก, บันทึกโควตา, อัปโหลดไฟล์, ลบและเปลี่ยนรูป และเปิดแท็บรหัสผ่าน

ยังไม่มีการรัน migration บนระบบจริงจากชุดงานนี้ ตัวทดสอบฐานข้อมูลใช้ PostgreSQL ภายในเครื่อง (PGlite) และ schema จำลอง Auth/Storage จึงต้องตรวจการเชื่อมต่อ Supabase จริงหลังติดตั้งด้วย

## ค่าตั้งต้น

| การตั้งค่า | ค่าเริ่มต้น |
| --- | --- |
| บ้านที่เป็นเจ้าของต่อผู้ใช้ | 1 บ้าน; บัญชีเดิมที่มีหลายบ้านจะได้รับขั้นต่ำตามจำนวนเดิม |
| พื้นที่ต่อบ้าน | 20 MB |
| ไฟล์ต่อครั้ง | 1 MB; admin ปรับได้สูงสุด 3 MB |
| รายการต่อบ้าน | 1,000 รายการ |
| สมาชิกต่อบ้าน | 5 คน |
| แพ็กเกจ | free, ไม่กำหนดวันหมดอายุ |

MB ในระบบหมายถึง 1,048,576 ไบต์ โควตานับรายการในตาราง `entries` และไฟล์ของบ้านในบักเก็ต `household-files` ไม่รวมรูปโปรไฟล์หรือคลังรหัสผ่านส่วนตัวในอุปกรณ์ รูปถูกย่อก่อนส่งตามขนาดที่แบบฟอร์มรองรับ; ค่าของ admin เป็นเพดานฝั่งเซิร์ฟเวอร์ แม้เรียก API ตรงก็ข้ามไม่ได้

พื้นที่รวมไฟล์ที่อัปโหลดแล้วและพื้นที่ที่จองระหว่างอัปโหลด เพื่อป้องกันคำขอพร้อมกันใช้พื้นที่เกิน ระบบจะไม่ลบข้อมูลเดิมเมื่อปรับโควตาต่ำกว่าที่ใช้อยู่ แต่จะปฏิเสธการเพิ่มเกินโควตา

## สิทธิ์และแพ็กเกจ

- เปิด/ปิดบัญชีและแก้จำนวนบ้านที่เป็นเจ้าของได้ ป้องกันการปิดบัญชี admin ของตัวเองและการเอาเจ้าของบ้านคนสุดท้ายออก
- เพิ่มบ้านให้ผู้ใช้ จัดการสมาชิก และเปลี่ยนบทบาท owner/admin/member ได้
- ปิดบ้านจะปิดการเข้าถึงข้อมูลบ้านทั้งหลัง ปิดบัญชีจะระงับข้อมูลผ่าน RLS และหยุดส่ง push ให้บัญชีนั้น หน้าจอตรวจซ้ำทุก 30 วินาทีและเมื่อกลับมาเปิดแท็บ
- การปิดบัญชีเป็นการปิดสิทธิ์ใช้งานแอป ไม่ได้ลบบัญชี Auth, ยกเลิก session ใน Supabase หรือเรียกคืนไฟล์ที่ดาวน์โหลดแล้ว; signed URL ที่เคยออกไปยังใช้ได้จนหมดอายุ
- ตั้งชื่อแพ็กเกจ สถานะ free/trial/active/past_due/canceled และวันใช้งานได้ถึงได้ วันที่หมดอายุใช้เวลาสิ้นวันของประเทศไทย
- เมื่อแพ็กเกจหมดอายุ หรือสถานะเป็น past_due/canceled ยังอ่านและลบรายการได้ แต่เพิ่มหรือแก้ไขไม่ได้
- ส่วน subscription เป็นการตั้งค่าสิทธิ์ด้วย admin ยังไม่เชื่อมระบบชำระเงิน ต่ออายุอัตโนมัติ หรือ webhook จากผู้ให้บริการชำระเงิน
- เก็บประวัติการแก้บัญชี บ้าน สมาชิก และการคืนพื้นที่ใน audit log

## ลบรูปและคืนพื้นที่

การลบรายการหรือเปลี่ยนรูปจะบันทึกการเปลี่ยนแปลงรายการก่อน จากนั้นตรวจข้อมูลที่บันทึกจริงและลบไฟล์เก่าผ่าน Storage API ถ้ามีรายการอื่นอ้างอิงอยู่จะไม่ลบ รวมถึงไฟล์แนบและรูปหลายรูปในรายการ

หากเครือข่ายขัดข้อง ระบบตรวจว่าการบันทึกสำเร็จจริงหรือไม่ก่อนลบไฟล์ใหม่ที่อัปโหลดไป ป้องกันการลบรูปของรายการที่บันทึกสำเร็จแล้ว การลบไฟล์ล้มเหลวจะแจ้งให้ลองบันทึกอีกครั้ง

ปุ่ม **คืนพื้นที่จากไฟล์ค้าง** ในหน้าบ้านของ admin ลบเฉพาะไฟล์/การจองอัปโหลดที่ไม่มีรายการอ้างอิงและมีอายุเกิน 24 ชั่วโมง ครั้งละสูงสุด 100 ไฟล์ สามารถกดซ้ำเพื่อจัดการส่วนที่เหลือ ไม่แก้หรือลบแถว `storage.objects` โดยตรง

## คัดลอกรหัสผ่าน 1 นาที

ปุ่มคัดลอกอยู่ท้ายช่องรหัสผ่านที่ซ่อนไว้ เริ่มนับ 60 วินาทีใหม่ทุกครั้งที่คัดลอก และปิดการแสดงรหัสผ่านอัตโนมัติภายใน 60 วินาที รหัสที่บันทึกในคลังยังคงอยู่ตามเดิม

หลังครบเวลา แอปจะพยายามล้างคลิปบอร์ดเฉพาะเมื่อค่ายังตรงกับที่คัดลอก ไม่ล้างข้อความใหม่ที่ผู้ใช้คัดลอกตามหลัง หากไม่มีสิทธิ์อ่าน/เขียนคลิปบอร์ดจะแจ้งให้ล้างด้วยปุ่มเอง จึงรับประกันการล้างภายใน 60 วินาทีไม่ได้บนทุกเบราว์เซอร์ โดยเฉพาะเมื่อปิดแท็บหรือพักแอป และไม่สามารถลบประวัติคลิปบอร์ดของระบบปฏิบัติการได้
